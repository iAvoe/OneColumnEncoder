# 1cenc 設計理念與特性

## 設計理念

### 動機贅述

影片壓製本質上是在畫質、速度、體積之間權衡的不可能三角，沒有絕對最佳的方案。大多數用戶只能通過大量試錯積累經驗，而即使是高級用戶，也常因參數、路徑、文本複製失誤或工具間的相容性與規範要求而出錯。為了避免錯誤，往往需要執行繁瑣的紀律性流程檢查，否則一次疏忽就可能浪費大量時間和算力。

影片壓製工具的生態系統十分碎片化，不同工具擁有各自獨立的語法、I/O 格式和工作流程。熟悉一種工具並不能輕鬆遷移到另一種，使得非專業用戶難以上手，而高級用戶學習新工具也需要投入不少時間。

配置一次壓制任務通常需要耗費大量精力，不僅降低工作效率，也削弱了高性能硬體帶來的速度優勢，占用了用戶大量的自由時間。

此外，大多數影片壓製工具的 UI 在布局、交互和狀態回饋等方面仍有不足，用戶可能需要頻繁切換窗口，對付控制項設計和預設值的不合理，使得直接編輯命令行參數反而更加高效好用。

### 核心定位

1cenc（OneColumnEncoder）是一款基於 .NET 9 / WPF 的 Windows 影片壓製輔助工具。它不試圖把影片壓製“傻瓜化”成黑盒，而是把常見、重複、容易出錯的步驟自動化，同時保留外部工具、腳本、編碼器參數和命令行的自訂。

1cenc 的設計方向是在硬核工作流和直觀 UI 之間取一個平衡點，讓用戶能快速完成壓制，也能在需要時看到並干預底層邏輯。

### 一列式 UI 交互

1cenc 採用“一列式”主界面：工具導入、上遊程序、編碼器、依賴項、影片源、腳本源、源檢查、編碼設置、啟動壓制等區域都按流程順序平鋪在主界面中，而不是藏進多級菜單。

這樣做的好處是：

- 常用操作可以直接在主界面完成，減少“進入設置頁再返回”的來回跳轉。
- 工具、源、檢查狀態和輸出設置能同時被看到，用戶更容易理解當前壓制鏈路。
- 選擇上游、編碼器、源文件、腳本源等操作大多可以壓縮到一次點擊或一次導入，相對的，打開下拉菜單再選擇需要至少兩次點擊，兩次游標移動，且按鈕面積更小，更難操作。

這樣做的代價是主界面偏長，需要滾動查看全貌。因此項目提供了 `▶▶` / `▼▼` 摺疊機制，用戶可以收起區域，只保留關鍵狀態。首次使用建議展開所有區域完整看一遍，熟悉流程後再按個人習慣摺疊。

### 主界面優先交互

1cenc 被設計為“盡量不進入二級配置界面也能開始壓制”。用戶導入工具、選擇源、分析源、設置輸出後，可以直接在主界面啟動任務。

二級窗口主要承擔以下職責：

- 編碼參數細調
- 並行 / NUMA / 執行緒設置
- 濾鏡與腳本編輯
- 取段打樣
- 壓制監控
- 應用設定與清理

#### 開始壓制按鈕的“阻塞條件”

這種使開始壓制按鈕變灰，無法點擊的條件主要來自必然會導致任務失敗的狀態，例如：

- 未導入/未選擇必要工具：至少需要上遊程序、編碼器和 ffprobe。
- 未導入影片源 / 隊列 / 合併源。
- 源影片損壞到無法被 ffprobe 正常打開和分析，缺少關鍵數據。
- 上遊程序與腳本源不匹配，例如 `vspipe` 需要 `.vpy`，`avs2yuv` / `avs2pipemod` 需要 `.avs`。
- `avs2pipemod` 與 `avisynth.dll` 依賴缺失。
- 輸出目錄不可寫、磁碟空間不足等硬體/系統問題。
- 輸出目錄存在同名文件時，覆蓋保護項會給出警告（編碼前置檢查卡中顯示為橙色），使開始壓制按鈕變灰；用戶可手動繞過檢查解除按鈕鎖定，但啟動壓制後還會根據被覆蓋檔案大小附加冷卻時間的二次確認彈出視窗

源檢查和編碼前置檢查中的一部分警告可以繞過。原則上是：錯誤用於阻止必然失敗或高風險流程，警告用於提醒用戶，但最終選擇權留給用戶。

### 低干擾配色與高可見提示色

1cenc 的普通 UI 元素傾向於低明度、低對比度設計，避免長時間配置和監控時產生視覺壓力。狀態提示色則採用更高辨識度的紅綠燈邏輯：

- 紅色：錯誤，通常阻止繼續。
- 橙黃：警告，建議處理，但可繞過。
- 青綠：成功、正常、已滿足條件。

這種設計讓用戶在主界面上可以快速掃視當前流程是否可運行，而不是逐項閱讀每個檢查項。

### 滑鼠友好設計

1cenc 的交互假設是：用戶可能懂壓制，但不一定想記住大量命令行。項目盡量讓所有操作都能用滑鼠完成。

UI 控制項大量使用：

- 卡片：表示工具、源、設置項和狀態。
- 下拉菜單：選擇工具導入類型、語言、編碼模式等。
- 滑條：配置 CRF、ABR、關鍵幀間隔、縮放比例、執行緒數等連續或分檔參數。
- 開關 / 勾選框：控制濾鏡、第三方參數、並行偏好等布爾選項。
- 可複製文本：顯示路徑、命令、日誌、分析 JSON 等資訊，按滑鼠右鍵的菜單即可打開或複製。

### 命令行展示機制

啟動壓制前會展示最終命令，編碼監控中也可以再次查看命令，方便用戶檢查和復現。

## 壓制模式

1cenc 支持三種主要源路線：單源模式、隊列模式、合併模式。

### 單源模式

單源模式是最普通的工作流：一個影片源或腳本源生成一個輸出。

可用路線包括：

- `ffmpeg` 直接讀取影片源並輸出 Y4M 管道。
- `vspipe` 讀取 VapourSynth `.vpy` 腳本。
- `avs2yuv` / `avs2pipemod` 讀取 AviSynth `.avs` 腳本。
- `OneLineShotArgs` 讀取 SVFI 相關源配置，用於 SVFI 路線。

單源模式支持取段打樣，用戶可以按時間或幀號截取片段壓製，用於快速驗證主觀壓制效果。

### 隊列模式

隊列模式用於“一批獨立影片源生成一批獨立輸出”，典型場景是 TV 劇集、BDRip 等已經完成分集，格式前後一致的影片串流。

隊列模式導入的是文件夾。導入後用 ffprobe 分析所有候選源，並根據一致性規則過濾掉格式不一致的影片串流。

#### 隊列篩選策略

1cenc 提供了兩種策略：

1. 以首個影片串流為參考，排除檢查結果差異過大的文件。
2. 加權投票後再以代表組為參考，適合 BDMV 目錄中混雜正片、片頭、預告、菜單小片段等情況。

#### 隊列模式特點

- 源文件數量等於輸出文件數量，一對一執行自動封裝。
- 每個任務按順序執行，不是並行跑滿多個編碼任務。
- 支持隊列側邊欄顯示 Pending、Encoding、Completed、Failed、Interrupted 等狀態。
- 為隊列生成一組 `.avs` / `.vpy` 腳本。
- 支持按最小時長過濾短片段。
- 不支持取段打樣。
- 不支持 `OneLineShotArgs` / SVFI 路線。

### 合併模式 / 拼接模式

合併模式用於“多個影片片段拼接出單個輸出”。主要用途是處理 BDMV 中被切成多個片段的正片，也就是過分集源或“肉醬盤”。

合併模式導入時會進行基礎相容檢查：

- 至少需要兩個影片檔案。
- 文件副檔名必須一致。
- 解析度必須一致。
- codec、像素格式、檢查清單簽名、幀率等差異會給出警告。
- VFR 和幀率簽名差異作為警告處理，引導用戶在濾鏡編輯器加上 VFR→CFR 修復設置。

合併模式會生成 `ffmpeg concat demuxer` 所需的 filelist，並可生成合併用 `.avs` / `.vpy` 腳本。濾鏡編輯器中也可以調整合並片段順序、移除片段，並重新生成 filelist。

合併模式的音訊處理是影片管道之外的封裝步驟：生成的 AVS/VPY 腳本只處理影片；編碼完成後，ffmpeg 會嘗試從 concat filelist 對應的源中拷貝音訊串流到最終 MKV。對於 VFR 源或邊界複雜的片段，音訊時長可能比影片長，建議合併壓製後再檢查並處理音訊。

## 壓制流程

### 外部編碼器優先設計

ffmpeg 自帶影片編碼器，但 1cenc 的正式壓制流程故意不以 ffmpeg 內建編碼器作為主編碼路線，而是把 ffmpeg / vspipe / avs2yuv 等作為上游解碼與濾鏡工具，把 x264 / x265 / SVT-AV1 等獨立程序作為下游編碼器。

正式編碼鏈路大致是：

```text
上遊程序輸出 Y4M -> 管道 -> 外部編碼器 -> 原始影片串流 -> 可選 ffmpeg 封裝
```

這樣做的原因是：

- 鼓勵使用獨立編碼器或第三方修改版編碼器。
- 鼓勵使用最新版編碼器，以及自己編譯編碼器（↑畫質、↑效率）
- 更容易利用編碼器原生參數和實驗參數。
- 對命令行編碼器更透明。
- 編碼命令可直接展示、複製和複查。
- 封裝在 ffmpeg 中的編碼器只能透過啟動編碼來看到編碼器版本，需要專門寫一個命令行參數（麻煩）。

代價是適配新編碼器更複雜。每個新編碼器都需要處理工具導入、版本檢測、參數 UI、預設、自動參數生成、輸出副檔名、封裝輸入格式等細節。

### 自動參數生成

1cenc 會基於 ffprobe 分析結果自動補充部分編碼參數，包括：

- 總幀數：用於 x264/x265 的 `--frames` 和 SVT-AV1 的 `-n`。
- 色彩矩陣（color matrix）、傳輸特質（transfer）、原色色系（primaries）。
- 亮度色度範圍（color range）。
- 色度採樣點位（chroma location）。
- x264/x265 的 lookahead。
- x265 的 `merange`、`subme`。
- 合併模式下使用所有片段總幀數，而不是只使用第一個片段幀數。

項目不會把所有參數都暴露成 UI 控制項，而是把常用參數做成滑條、預設、開關，把更高級或更不穩定的內容留給自訂參數文本框。

#### 總幀數自動修復

1cenc 會在影片元數據中缺少總幀數時用 $ \lfloor T \cdot R_{\text{avg}} + 0.5 \rfloor $ 補充，並寫入 ffprobe 分析 JSON 中
- T：時長
- $R_{\text{avg}}$：平均幀率
- $\lfloor$ $\rfloor$：下取整（floor）

### 輸出與自動封裝

編碼器會先輸出對應的原始影片串流：

- x264：`.mp4`
- x265：`.hevc`
- SVT-AV1：`.ivf`

如果已導入 ffmpeg，項目會生成封裝命令，把編碼後的影片串流與源文件中的音訊、字幕、章節、元數據等合併到 MKV。單源和隊列模式會盡量從原影片複製非影片串流；合併模式會從 concat filelist 複製音訊串流。

封裝是可控步驟，編碼監控窗口中可以看到封裝命令和狀態。對於 x265 / SVT-AV1 這類原始流輸出，封裝後能夠更容易添加新流，也更容易轉換到其它的封裝格式，因此會默認勾選。

## 源分析與檢查清單

1cenc 依賴 ffprobe 讀取源影片元數據。源檢查包括兩類：

硬性問題：

- 元數據無法讀取。
- 非逐行掃描。
- 位深超過支持範圍。
- SVT-AV1 當前不支持的 12-bit 輸入。
- 其他會導致參數生成或編碼明顯不可靠的問題。

軟性問題：

- VFR / 非恆定幀率。
- SAR 不是 1:1 / 非方形象素。
- 色彩矩陣缺失。
- transfer 缺失。
- primaries 缺失。
- 色度採樣 / chroma subsampling / chroma location 可能不適合當前編碼器。

硬性問題一般阻止開始壓制；軟性問題會提示用戶使用濾鏡編輯器或自行確認後繞過。

## 濾鏡與腳本編輯器

濾鏡編輯器是 1cenc 的輔助模組。它支持：

- 一鍵生成 AviSynth(+) `.avs` 腳本。
- 一鍵生成 VapourSynth `.vpy` 腳本。
- 為隊列批次生成對應腳本。
- 為合併模式生成包含多個片段的合併腳本。
- 生成或提示 ffmpeg 濾鏡參數。
- VFR→CFR 轉換。
- SAR 修復。
- 解析度縮放。
- 色彩空間轉換。
- HDR→SDR 相關轉換。
- hqdn3d 降噪範例。
- 字幕燒錄範例。
- 自訂 ffmpeg 濾鏡命令行參數。
- 自訂 AviSynth(+)、VapourSynth 濾鏡腳本行。

對於腳本源，項目會校驗腳本裡嵌入的影片路徑是否與當前影片源匹配。隊列腳本會按檔案名和嵌入路徑做對應關係檢查，避免腳本和源錯位。合併模式因為腳本天然包含多個源，會跳過單源路徑匹配，改由合併源導入與分析階段保證合理性。

## 編碼參數與預覽

編碼設置支持 x264、x265、SVT-AV1 的 CRF / ABR、預設、關鍵幀間隔和部分第三方參數開關。項目的設計不是把編碼器所有參數做成表單，而是根據影片編碼器開發者的意圖來構建預設。

項目還提供單圖壓制 A/B 預覽功能：

- 從源影片指定位置抽幀。
- 使用 ffmpeg 的 libx264 / libx265 / libsvtav1 / libvvenc 做單幀預覽編碼。
- 解碼後與原圖進行 A/B 對比。
- 支持不同顯示模式，如原始顯示、低色域到 BT.709、WCG 到 BT.709、HDR 到 SDR 等。
- 如果隨包存在 SSIMULACRA2.1、Butteraugli 工具，會計算圖像畫質跑分。

預覽功能用於快速觀察參數影響，質量上取決於影片編碼器對單幀編碼處理效果優於或劣於幀間冗餘，因此不等同於正式壓制管線。

## 並行與硬體調度

1cenc 在這裡深度依賴 Windows API，因此項目明確面向 Windows，而不是跨平台工具。

並行設置包括：

- 上遊程序 NUMA 節點。
- 下游編碼器 NUMA 節點。
- 是否偏好物理核心。
- 編碼器執行緒數限制。
- x264 執行緒參數。
- x265 pools 參數。
- CPU Sets 綁定。

項目不會提升進程優先度。設計上更重視系統仍能響應，避免編碼器失控卡死時拖垮整個系統的響應。

編碼前置檢查還包括：

- 是否接入 AC 電源。
- 輸出目錄是否可寫。
- 磁碟空間是否足夠。
- 輸出文件是否會覆蓋。
- Avs2Yuv 路線所需的 L-SMASH 插件是否存在。
- 當前 NUMA 節點 CPU 占用是否偏高。

其中覆蓋檢查不僅會提示，還會根據被覆蓋檔案大小延遲啟用確認按鈕，降低誤覆蓋大文件的機率。

## 編碼監控

編碼監控窗口負責運行上游和下游進程，並把上游 stdout 管道傳給編碼器 stdin。它會同時讀取上游和下游 stderr，用於顯示日誌和解析進度。

監控功能包括：

- 上游 / 下游日誌分欄。
- 日誌摺疊，避免重複行洗版。
- 保存上游 / 下游 stderr。
- 查看編碼命令。
- 進度百分比。
- 已寫幀數。
- 當前輸出大小。
- 預計輸出大小。
- 已用時間、剩餘時間、預計完成時間。
- 上游 / 下游記憶體占用。
- 工作集峰值、Page Fault、記憶體壓力。
- 手動中斷上游或編碼器。
- 編碼完成後才允許關閉窗口。
- 隊列模式下顯示每個任務的狀態。

隊列任務按順序執行，失敗時停止後續任務；用戶中斷後可以選擇是否停止剩餘隊列。

## 工具導入與可移植性

1cenc 默認所在系統沒有配置任何系統路徑。用戶可以導入外部工具路徑，項目會保存工具路徑、版本和檔案大小。

支持導入的工具包括：

- 上游：`ffmpeg.exe`、`vspipe.exe`、`avs2yuv.exe`、`avs2pipemod.exe`、`one_line_shot_args.exe`
- 編碼器：`x264.exe`、`x265.exe`、`svtav1encapp.exe`
- 分析 / 依賴：`ffprobe.exe`、`avisynth.dll`

首次啟動時，項目會嘗試自動發現部分工具，例如 VapourSynth 的 `vspipe.exe` 和 Steam 發行版 SVFI 的 `one_line_shot_args.exe`。

發布包可以附帶常用編碼器和分析工具，但項目理念上仍鼓勵用戶替換為自己信任的新版或第三方修改版工具。

## 產生的配置與臨時文件

### 應用配置目錄

所有主要持久化配置存放在應用程式基目錄下的 `1cenc` 文件夾中：

- `appconfig.json`：應用設定、語言、覆蓋確認行為。
- `appdata.json`：工具路徑、版本、大小、源路徑、輸出目錄、主界面摺疊狀態等。
- `encodingconfig.json`：編碼參數配置。
- `parallelismconfig.json`：並行與 NUMA 設置。

### 隊列模式

隊列源分析會在 `1cenc` 配置目錄下生成時間戳 JSON：

- `source_queue_yyyyMMdd_HHmmss.json`：被接受的隊列源及對應 ffprobe JSON。
- `source_queue_excluded_yyyyMMdd_HHmmss.json`：被過濾或排除的源。

設置界面可以清理 7 天前生成的 `source_queue_*.json` 文件。

### 合併模式

合併模式會在 `1cenc` 配置目錄下生成：

- `source_concat_filelist.txt`

該文件使用 ffmpeg concat demuxer 格式，記錄當前合併片段順序。用戶在濾鏡編輯器中調整順序或刪除片段時會重新生成。

### 腳本文件

濾鏡編輯器和一鍵腳本生成會在用戶選擇的位置生成：

- `.avs`
- `.vpy`
- 有時也可能保存 `.txt` 形式的 ffmpeg filter / filelist 內容

預設使用源檔案名作為腳本檔案名。隊列模式會為每個源生成同名腳本。

### LWLibavVideoSource / LWLibavSource 索引

AviSynth 和 VapourSynth 腳本中使用 L-SMASH / LWLibav 讀取影片時，底層插件可能在影片源目錄生成索引文件（`.lwi`）。這是解碼插件行為，不是 1cenc 自己的設定檔。

### 預覽與日誌

單圖預覽會在系統臨時目錄創建 `1cenc-image-preview-*` 工作目錄，窗口關閉時會嘗試刪除。

編碼監控中保存日誌時，會在用戶選擇的輸出位置寫：

- `upstream-stderr.txt`
- `downstream-stderr.txt`

## 當前限制

- 僅面向 Windows。項目依賴 WPF、CPU Sets、NUMA、進程與記憶體相關 Windows API。
- 正式編碼器目前主要支持 x264、x265、SVT-AV1。
- SVT-AV1 當前不支持 12-bit 輸入。
- 隊列模式和合併模式不支持取段打樣。
- `OneLineShotArgs` / SVFI 路線不支持隊列和合併模式。
- 合併模式音訊封裝可用，但複雜 VFR 或邊界異常源仍建議後處理。
- 項目當前沒有完整自動化測試，主要依靠功能驗證和實際長隊列測試。
