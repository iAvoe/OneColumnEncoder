# 1cenc 设计理念与特性

## 设计理念

### 动机赘述

视频压制本质上是在画质、速度、体积之间权衡的不可能三角，没有绝对的最优解。新手和菜鸟只能通过大量试错积累经验，而即使是高级用户，也常因参数、路径、文本拷贝失误、工具间兼容性与规范要求等细节上出错；且依此演变为繁琐的纪律性流程检查，否则一点疏忽就只能推倒重来，但无论怎样，这些事项不仅麻烦，还拖累了高性能硬件带来的速度优势。

视频压制工具的生态系统十分碎片化：有的工具过于傻瓜化；有的则如同核电站控制台一般复杂，有的是为解决专用问题的非通用方案，有的则是因数十年的更新而大量保留了过时的功能设计。此外，还有 UI/UX 等方面略欠调校的问题，如用户可能需要频繁切换窗口，过时的默认值，按下按钮没有视觉反馈等... 种种问题使得任何级别的用户都需要花费不少时间来熟悉操作；反倒是交互逻辑统一而容易上手的命令行界面反而更加高效好用了。

### 核心定位

1cenc（OneColumnEncoder）是一款基于 .NET 9 / WPF 的 Windows 视频压制辅助工具。它不试图把视频压制“傻瓜化”成黑盒，而是把常见、重复、容易出错的步骤自动化，同时保留外部工具、脚本、编码器参数和命令行的自定义。

1cenc 的设计方向是在硬核工作流和直观 UI 之间取一个平衡点，让用户能快速完成压制，也能在需要时看到并干预底层逻辑。

### 一列式 UI 交互

1cenc 采用“一列式”主界面：工具导入、上游程序、编码器、依赖项、视频源、脚本源、源检查、编码设置、启动压制等区域都按流程顺序平铺在主界面中，而不是藏进多级菜单。

这样做的好处是：

- 常用操作可以直接在主界面完成，减少“进入设置页再返回”的来回跳转。
- 工具、源、检查状态和输出设置能同时被看到，用户更容易理解当前压制链路。
- 选择上游、编码器、源文件、脚本源等操作大多可以压缩到一次点击或一次导入，相对的，打开下拉菜单再选择需要至少两次点击，两次光标移动，且按钮面积更小，更难操作。

这样做的代价是主界面偏长，需要滚动查看全貌。因此项目提供了 `▶▶` / `▼▼` 折叠机制，用户可以收起区域，只保留关键状态。首次使用建议展开所有区域完整看一遍，熟悉流程后再按个人习惯折叠。

### 主界面优先交互

1cenc 被设计为“尽量不进入二级配置界面也能开始压制”。用户导入工具、选择源、分析源、设置输出后，可以直接在主界面启动任务。

二级窗口主要承担以下职责：

- 编码参数细调
- 并行 / NUMA / 线程设置
- 滤镜与脚本编辑
- 取段打样
- 压制监控
- 应用设置与清理

#### 开始压制按钮的“阻塞条件”

这种使开始压制按钮变灰，无法点击的条件主要来自必然会导致任务失败的状态，例如：

- 未导入/未选择必要工具：至少需要上游程序、编码器和 ffprobe。
- 未导入视频源 / 队列 / 合并源。
- 源视频损坏到无法被 ffprobe 正常打开和分析，缺少关键数据。
- 上游程序与脚本源不匹配，例如 `vspipe` 需要 `.vpy`，`avs2yuv` / `avs2pipemod` 需要 `.avs`。
- `avs2pipemod` 与 `avisynth.dll` 依赖缺失。
- 输出目录不可写、磁盘空间不足等硬件/系统问题。
- 输出目录存在同名文件时，覆盖保护项会给出警告（编码前置检查卡中显示为橙色），使开始压制按钮变灰；用户可手动绕过检查解除按钮锁定，但启动压制后还会根据被覆盖文件大小附加冷却时间的二次确认弹窗

源检查和编码前置检查中的一部分警告可以绕过。原则上是：错误用于阻止必然失败或高风险流程，警告用于提醒用户，但最终选择权留给用户。

### 低干扰配色与高可见提示色

1cenc 的普通 UI 元素倾向于低明度、低对比度设计，避免长时间配置和监控时产生视觉压力。状态提示色则采用更高辨识度的交通灯逻辑：

- 红色：错误，通常阻止继续。
- 橙黄：警告，建议处理，但可绕过。
- 青绿：成功、正常、已满足条件。

这种设计让用户在主界面上可以快速扫视当前流程是否可运行，而不是逐项阅读每个检查项。

### 鼠标友好设计

1cenc 的交互假设是：用户可能懂压制，但不一定想记住大量命令行。项目尽量让所有操作都能用鼠标完成。

UI 控件大量使用：

- 卡片：表示工具、源、设置项和状态。
- 下拉菜单：选择工具导入类型、语言、编码模式等。
- 滑条：配置 CRF、ABR、关键帧间隔、缩放比例、线程数等连续或分档参数。
- 开关 / 勾选框：控制滤镜、第三方参数、并行偏好等布尔选项。
- 可复制文本：显示路径、命令、日志、分析 JSON 等信息，按鼠标右键的菜单即可打开或复制。

### 命令行展示机制

启动压制前会展示最终命令，编码监控中也可以再次查看命令，方便用户检查和复现。

## 压制模式

1cenc 支持四种主要源路线：单源模式、队列模式、合并模式、重分集模式。

### 单源模式

单源模式是最普通的工作流：一个视频源或脚本源生成一个输出。

可用路线包括：

- `ffmpeg` 直接读取视频源并输出 Y4M 管道。
- `vspipe` 读取 VapourSynth `.vpy` 脚本。
- `avs2yuv` / `avs2pipemod` 读取 AviSynth `.avs` 脚本。
- `OneLineShotArgs` 读取 SVFI 相关源配置，用于 SVFI 路线。

单源模式支持取段打样，用户可以按时间或帧号截取片段压制，用于快速验证主观压制效果。

### 队列模式

队列模式用于“一批独立视频源生成一批独立输出”，典型场景是 TV 剧集、BDRip 等已经完成分集，格式前后一致的视频流。

队列模式导入的是文件夹。导入后用 ffprobe 分析所有候选源，并根据一致性规则过滤掉格式不一致的视频流。

#### 队列筛选策略

1cenc 提供了两种策略：

1. 以首个视频流为参考，排除检查结果差异过大的文件。
2. 加权投票后再以代表组为参考，适合 BDMV 目录中混杂正片、片头、预告、菜单小片段等情况。

#### 队列模式特点

- 源文件数量等于输出文件数量，一对一执行自动封装。
- 每个任务按顺序执行，不是并行跑满多个编码任务。
- 支持队列侧边栏显示 Pending、Encoding、Completed、Failed、Interrupted 等状态。
- 为队列生成一组 `.avs` / `.vpy` 脚本。
- 支持按最小时长过滤短片段。
- 不支持取段打样。
- 不支持 `OneLineShotArgs` / SVFI 路线。

### 合并模式 / 拼接模式

合并模式用于“多个视频片段拼接出单个输出”。主要用途是处理 BDMV 中被切成多个片段的正片，也就是过分集源或“肉酱盘”。

合并模式导入时会进行基础兼容检查：

- 至少需要两个视频文件。
- 文件扩展名必须一致。
- 分辨率必须一致。
- codec、像素格式、检查清单签名、帧率等差异会给出警告。
- VFR 和帧率签名差异作为警告处理，引导用户在滤镜编辑器加上 VFR→CFR 修复设置。

合并模式会生成 `ffmpeg concat demuxer` 所需的 filelist，并可生成合并用 `.avs` / `.vpy` 脚本。滤镜编辑器中也可以调整合并片段顺序、移除片段，并重新生成 filelist。

合并模式的音频处理是视频管道之外的封装步骤：生成的 AVS/VPY 脚本只处理视频；编码完成后，ffmpeg 会尝试从 concat filelist 对应的源中拷贝音频流到最终 MKV。对于 VFR 源或边界复杂的片段，音频时长可能比视频长，建议合并压制后再检查并处理音频。

### 重分集模式

重分集模式把一个或多个视频流格式完全一致的 CFR 源按顺序组成虚拟帧时间轴，再由用户手动划分为任意数量的独立分集输出，可同时处理一个物理文件内包含多集和一集横跨多个物理文件的情况。

专用配置窗口提供输入/输出双侧栏、按帧数比例绘制的分区图、同步的时间与帧输入、允许保留的未分配区间，以及相邻分集合并。首版不读取章节或 MPLS，也不复制源音频、字幕、章节和元数据；每个输出独立压制并封装为 video-only MKV。

**容器级时间粒度会被归一化，不属于格式签名。** 重分集的严格源签名比较的是真正的视频格式字段（编码、profile、level、尺寸、像素格式、颜色元数据、帧率、extradata），但有意排除逐流的 `time_base`——封装层的时间刻度，例如同为 24000/1001 fps 时 `1/24000` 与 `1/96000` 的差别。它是容器细节而非视频格式属性，因此即使同一批压制结果以不同刻度封装各集，仍可视为同一条虚拟时间轴。这样做是安全的，因为所有上游都会归一化时间：ffmpeg 先重置每个输入的 PTS 再按方案帧率重建 CFR PTS 序列，VapourSynth/AviSynth 按帧拼接，最终 video-only MKV 使用取自参考源的 `-video_track_timescale`。

#### 拼接后再裁剪（Concat then Split）

重分集模式按上游工具把“先拼接成一条虚拟帧时间轴、再按输出段裁剪”的命令落地如下：

- **ffmpeg**：逐个打开全部源（`-i 源1 -i 源2 ...`），只映射各源 `v:0`，先用 `concat` 滤镜按导入顺序拼接成单条视频，再以帧级 `trim=start_frame=首帧:end_frame=末帧+1` 裁出当前输出段，最后用 `setpts` 重建从 0 开始的 CFR PTS 序列；单源时省略 concat，直接对源施加帧级 `trim`。
- **vspipe**：生成包含全部源的拼接脚本（`core.std.Splice`），再以 `-s {首帧} -e {末帧}` 在 vspipe 命令行层面切片。
- **avs2yuv / avs2pipemod**：生成包含全部源的拼接脚本（AviSynth `++` UnalignedSplice），avs2yuv 用 `-seek {首帧} -frames {帧数}`，avs2pipemod 用 `-trim={首帧},{末帧}` 切片。

重分集的切片以导入源在分析阶段实测的原始帧号为基准，跨源累计成全局帧索引，因此输出段边界在拼接后依然精确。每次编码开始都会生成本次执行专用的 concat filelist 与虚拟源脚本，外部脚本不会因过期或重排而使已划分的帧偏移失效。

#### 滤镜使用重分集视频流且不改写源

重分集模式有一条不可违背的约束：**导入的视频源本身绝对不被修改**。滤镜编辑器通过类似合并模式的临时重分集视频流工作；重分集源队列可以调整顺序，但导入文件和已确定的帧边界不变。原因在于：

- 分析阶段已按导入源的原始帧率、分辨率和逐帧时间戳建立虚拟时间轴；
- 一旦任何源被单独改写，各源之间将无法可靠拼接，已划分的输出段也可能整体错位；
- 因此源 Reviser 对活动重分集方案仍不可用，但滤镜编辑器可以使用重分集专用的合并式流程。它会对当前重分集源队列生成临时视频流并应用所选滤镜，同时保持导入源文件和已确定的帧边界不变。

## 压制流程

### 外部编码器优先设计

ffmpeg 自带视频编码器，但 1cenc 的正式压制流程故意不以 ffmpeg 内置编码器作为主编码路线，而是把 ffmpeg / vspipe / avs2yuv 等作为上游解码与滤镜工具，把 x264 / x265 / SVT-AV1 等独立程序作为下游编码器。

正式编码链路大致是：

```text
上游程序输出 Y4M -> 管道 -> 外部编码器 -> 原始视频流 -> 可选 ffmpeg 封装
```

这样做的原因是：

- 鼓励使用独立编码器或第三方修改版编码器。
- 鼓励使用最新版编码器，以及自己编译编码器（↑画质、↑效率）
- 更容易利用编码器原生参数和实验参数。
- 对命令行编码器更透明。
- 编码命令可直接展示、复制和复查。
- 封装在 ffmpeg 中的编码器只能通过启动编码来看到编码器版本，需要专门写一个命令行参数（麻烦）。

代价是适配新编码器更复杂。每个新编码器都需要处理工具导入、版本检测、参数 UI、预设、自动参数生成、输出扩展名、封装输入格式等细节。

### 自动参数生成

1cenc 会基于 ffprobe 分析结果自动补充部分编码参数，包括：

- 总帧数：用于 x264/x265 的 `--frames` 和 SVT-AV1 的 `-n`。
- 色彩矩阵（color matrix）、传输特质（transfer）、原色色系（primaries）。
- 亮度色度范围（color range）。
- 色度采样点位（chroma location）。
- x264/x265 的 lookahead。
- x265 的 `merange`、`subme`。
- 合并模式下使用所有片段总帧数，而不是只使用第一个片段帧数。

项目不会把所有参数都暴露成 UI 控件，而是把常用参数做成滑条、预设、开关，把更高级或更不稳定的内容留给自定义参数文本框。

#### 帧数策略

1cenc 在视频元数据中缺少总帧数时不会再用时长和平均帧率去推断。这样可以避免把猜出来的帧数带进编码器帧数限制或编码监控进度显示；在这种情况下，帧数相关进度会被省略。

### 输出与自动封装

编码器会先输出对应的原始视频流：

- x264：`.mp4`
- x265：`.hevc`
- SVT-AV1：`.ivf`

如果已导入 ffmpeg，项目会生成封装命令，把编码后的视频流与源文件中的音频、字幕、章节、元数据等合并到 MKV。单源和队列模式会尽量从原视频复制非视频流；合并模式会从 concat filelist 复制音频流。

封装是可控步骤，编码监控窗口中可以看到封装命令和状态。对于 x265 / SVT-AV1 这类原始流输出，封装后能够更容易添加新流，也更容易转换到其它的封装格式，因此会默认勾选。

## 源分析与检查清单

1cenc 依赖 ffprobe 读取源视频元数据。源检查包括两类：

硬性问题：

- 元数据无法读取。
- 非逐行扫描。
- 位深超过支持范围。
- SVT-AV1 当前不支持的 12-bit 输入。
- 其他会导致参数生成或编码明显不可靠的问题。

软性问题：

- VFR / 非恒定帧率。
- SAR 不是 1:1 / 非方形像素。
- 色彩矩阵缺失。
- transfer 缺失。
- primaries 缺失。
- 色度采样 / chroma subsampling / chroma location 可能不适合当前编码器。

硬性问题一般阻止开始压制；软性问题会提示用户使用滤镜编辑器或自行确认后绕过。

## 滤镜与脚本编辑器

滤镜编辑器是 1cenc 的辅助模块。它支持：

- 一键生成 AviSynth(+) `.avs` 脚本。
- 一键生成 VapourSynth `.vpy` 脚本。
- 为队列批量生成对应脚本。
- 为合并模式生成包含多个片段的合并脚本。
- 生成或提示 ffmpeg 滤镜参数。
- VFR→CFR 转换。
- SAR 修复。
- 分辨率缩放。
- 色彩空间转换。
- HDR→SDR 相关转换。
- hqdn3d 降噪示例。
- 字幕烧录示例。
- 自定义 ffmpeg 滤镜命令行参数。
- 自定义 AviSynth(+)、VapourSynth 滤镜脚本行。

对于脚本源，项目会校验脚本里嵌入的视频路径是否与当前视频源匹配。队列脚本会按文件名和嵌入路径做对应关系检查，避免脚本和源错位。合并模式因为脚本天然包含多个源，会跳过单源路径匹配，改由合并源导入与分析阶段保证合理性。

重分集模式下可以使用滤镜编辑器的重分集专用合并式流程。左侧队列显示重分集计划生成的输出分集；临时 AVS/VPY 拼接源或 ffmpeg 输入则在内部根据重分集源列表生成，并应用所选滤镜。导入源文件和已确定的帧边界不会被修改。源 Reviser 仍不可用，若要改变源的帧率或分辨率，应先重新建立重分集方案。

## 编码参数与预览

编码设置支持 x264、x265、SVT-AV1 的 CRF / ABR、预设、关键帧间隔和部分第三方参数开关。项目的设计不是把编码器所有参数做成表单，而是根据视频编码器开发者的意图来构建预设。

项目还提供单图压制 A/B 预览功能：

- 从源视频指定位置抽帧。
- 使用 ffmpeg 的 libx264 / libx265 / libsvtav1 / libvvenc 做单帧预览编码。
- 解码后与原图进行 A/B 对比。
- 支持不同显示模式，如原始显示、低色域到 BT.709、WCG 到 BT.709、HDR 到 SDR 等。
- 如果随包存在 SSIMULACRA2.1、Butteraugli 工具，会计算图像画质跑分。

预览功能用于快速观察参数影响，质量上取决于视频编码器对单帧编码处理效果优于或劣于帧间冗余，因此不等同于正式压制管线。

## 并行与硬件调度

1cenc 在这里深度依赖 Windows API，因此项目明确面向 Windows，而不是跨平台工具。

并行设置包括：

- 上游程序 NUMA 节点。
- 下游编码器 NUMA 节点。
- 是否偏好物理核心。
- 编码器线程数限制。
- x264 线程参数。
- x265 pools 参数。
- CPU Sets 绑定。

项目不会提升进程优先级。设计上更重视系统仍能响应，避免编码器失控卡死时拖垮整个系统的响应。

编码前置检查还包括：

- 是否接入 AC 电源。
- 输出目录是否可写。
- 磁盘空间是否足够。
- 输出文件是否会覆盖。
- Avs2Yuv 路线所需的 L-SMASH 插件是否存在。
- 当前 NUMA 节点 CPU 占用是否偏高。

其中覆盖检查不仅会提示，还会根据被覆盖文件大小延迟启用确认按钮，降低误覆盖大文件的概率。

## 编码监控

编码监控窗口负责运行上游和下游进程，并把上游 stdout 管道传给编码器 stdin。它会同时读取上游和下游 stderr，用于显示日志和解析进度。

监控功能包括：

- 上游 / 下游日志分栏。
- 日志折叠，避免重复行刷屏。
- 保存上游 / 下游 stderr。
- 查看编码命令。
- 仅在总帧数可靠时显示进度百分比。
- 仅在总帧数可靠时显示已写帧数。
- 当前输出大小。
- 进度可用时才显示预计输出大小。
- 进度可用时才显示已用时间、剩余时间、预计完成时间。
- 上游 / 下游内存占用。
- 工作集峰值、Page Fault、内存压力。
- 手动中断上游或编码器。
- 编码完成后才允许关闭窗口。
- 队列模式下显示每个任务的状态。

队列任务按顺序执行，失败时停止后续任务；用户中断后可以选择是否停止剩余队列。

## 工具导入与可移植性

1cenc 默认所在系统没有配置任何系统路径。用户可以导入外部工具路径，项目会保存工具路径、版本和文件大小。

支持导入的工具包括：

- 上游：`ffmpeg.exe`、`vspipe.exe`、`avs2yuv.exe`、`avs2pipemod.exe`、`one_line_shot_args.exe`
- 编码器：`x264.exe`、`x265.exe`、`svtav1encapp.exe`
- 分析 / 依赖：`ffprobe.exe`、`avisynth.dll`

首次启动时，项目会尝试自动发现部分工具，例如 VapourSynth 的 `vspipe.exe` 和 Steam 发行版 SVFI 的 `one_line_shot_args.exe`。

发布包可以附带常用编码器和分析工具，但项目理念上仍鼓励用户替换为自己信任的新版或第三方修改版工具。

## 产生的配置与临时文件

### 应用配置目录

所有主要持久化配置存放在应用程序基目录下的 `1cenc` 文件夹中：

- `appconfig.json`：应用设置、语言、覆盖确认行为。
- `appdata.json`：工具路径、版本、大小、源路径、输出目录、主界面折叠状态等。
- `encodingconfig.json`：编码参数配置。
- `parallelismconfig.json`：并行与 NUMA 设置。

### 队列模式

队列源分析会在 `1cenc` 配置目录下生成时间戳 JSON：

- `source_queue_yyyyMMdd_HHmmss.json`：被接受的队列源及对应 ffprobe JSON。
- `source_queue_excluded_yyyyMMdd_HHmmss.json`：被过滤或排除的源。

设置界面可以清理 7 天前生成的 `source_queue_*.json` 文件。

### 合并模式

合并模式会在 `1cenc` 配置目录下生成：

- `source_concat_filelist.txt`

该文件使用 ffmpeg concat demuxer 格式，记录当前合并片段顺序。用户在滤镜编辑器中调整顺序或删除片段时会重新生成。

### 脚本文件

滤镜编辑器和一键脚本生成会在用户选择的位置生成：

- `.avs`
- `.vpy`
- 有时也可能保存 `.txt` 形式的 ffmpeg filter / filelist 内容

默认使用源文件名作为脚本文件名。队列模式会为每个源生成同名脚本。

### LWLibavVideoSource / LWLibavSource 索引

AviSynth 和 VapourSynth 脚本中使用 L-SMASH / LWLibav 读取视频时，底层插件可能在视频源目录生成索引文件（`.lwi`）。这是解码插件行为，不是 1cenc 自己的配置文件。

### 预览与日志

单图预览会在系统临时目录创建 `1cenc-image-preview-*` 工作目录，窗口关闭时会尝试删除。

编码监控中保存日志时，会在用户选择的输出位置写：

- `upstream-stderr.txt`
- `downstream-stderr.txt`

## 当前限制

- 仅面向 Windows。项目依赖 WPF、CPU Sets、NUMA、进程与内存相关 Windows API。
- 正式编码器目前主要支持 x264、x265、SVT-AV1。
- SVT-AV1 当前不支持 12-bit 输入。
- 队列模式、合并模式和重分集模式不支持取段打样。
- `OneLineShotArgs` / SVFI 路线不支持队列、合并和重分集模式。
- 重分集模式当前要求 CFR、可靠的逐帧时间戳、完全一致的视频流格式、手动输出边界，以及用于生成 video-only MKV 的 ffmpeg。
- 合并模式音频封装可用，但复杂 VFR 或边界异常源仍建议后处理。
- 项目当前没有完整自动化测试，主要依靠功能验证和实际长队列测试。
